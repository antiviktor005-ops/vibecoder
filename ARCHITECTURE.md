# Архитектура VibeWorker AI

## Поток данных

```text
Личный чат Telegram → AdminGate → handlers → Commands → PostgreSQL
                                                ↓
                                        резерв в ai_usage
                                                ↓
                                     OpenAI → проверка Pydantic
                                                ↓
                                анализ / черновик / Jinja2 → ZIP
APScheduler → HTTPS с проверкой DNS → адаптер → фильтры → jobs + notifications
                                                            ↓
                                                    Telegram владельца
```

`app/main.py` собирает зависимости, подключает long polling и останавливает планировщик и клиентов при завершении. Один процесс последовательно обрабатывает пользовательские сообщения. Фоновый обход выполняется отдельной задачей. `app/config.py` загружает Secrets и типизированные лимиты через Pydantic Settings. `app/core` определяет ошибки, которые можно показать владельцу.

## Постоянное состояние

| Таблицы | Назначение |
| --- | --- |
| users, settings | ID владельца и настройки фильтрации и уведомлений |
| sources, jobs | Источники с результатом последней попытки и уникальные карточки заказов |
| analyses, drafts | История сгенерированных оценок и откликов по заказу |
| projects, artifacts | Проект и его ZIP в BYTEA. Сохраняются одной транзакцией |
| notifications | Очередь новых заказов с уникальным job_id и индикатором доставки |
| ai_usage | Суточный журнал резервов и расчётов с моделью, типом операции, токенами и суммой |

Alembic хранит версионированную схему. PostgreSQL advisory lock сериализует миграции. Уникальный SHA-256 отпечаток и INSERT ON CONFLICT закрывают гонку за один заказ. Для отпечатка используется ссылка без фрагмента, затем стабильный ID в пределах источника, в крайнем случае нормализованный текст. Пересылка той же публикации из источника с другой ссылкой может создать отдельную карточку.

## Поиск

`app/integrations/feeds.py` регистрирует адаптеры, каждый из которых преобразует загруженные байты в последовательность Listing. Сетевой доступ общий для всех адаптеров. RSS/Atom проходят XML-проверку с запретом DTD перед feedparser. JSON API использует валидацию полей. За цикл обрабатываются до 50 первых записей каждого из 20 источников. Источники без пагинации могут пропускать старые записи за пределами этого окна.

`app/scheduler` использует один async lock для ручного и планового обхода. Добавление заказа и постановка уведомления в очередь происходят в одной транзакции. При сбое Telegram запись остаётся до следующего цикла. Отправка происходит максимум по 30 уведомлений за проход. При падении между успешной отправкой и отметкой в БД возможно повторное уведомление. Команда отключения уведомлений приостанавливает доставку старой очереди и отключает постановку новых заказов в очередь.

## ИИ и сайты

Перед обращением к API сервис блокирует строку настроек через SELECT FOR UPDATE, проверяет три суточных лимита и фиксирует резерв отдельной транзакцией. Верхняя оценка входа основана на размере UTF-8 сообщений с запасом на форматирование. Лимит вывода составляет 1600 токенов. После ответа с usage резерв заменяется фактическими токенами и стоимостью по настроенным ставкам. При сетевой неопределённости он сохраняется. Платные запросы автоматически не повторяются. Учёт охватывает только этот экземпляр приложения и зависит от указанных тарифов.

ТЗ передаётся в пользовательской роли как JSON. Системное сообщение описывает задачу и указывает считать содержимое ТЗ недоверенным. Модель не получает инструментов или доступа к переменным окружения. Вывод проверяется по схеме. Попытки внедрения инструкций могут повлиять на содержание текста, поэтому владелец проверяет его перед использованием.

Для сайта модель выбирает палитру и генерирует заголовки, вводный текст и секции. Jinja2 экранирует текст. CSS и JS входят в проверенный шаблон. Генератор пишет три фиксированных имени файлов в ZIP в памяти. Число секций и длины полей ограничены схемой. Произвольный код и команды ОС не исполняются.

## Границы доступа

Общий middleware применяется к сообщениям и callback-запросам до выполнения handlers. Проверяются ID отправителя, тип и ID чата. Ограничение администратора составляет 30 действий за минуту. Принимаются текстовые команды и известные кнопки. Вложения из Telegram бот не загружает.

Для источников разрешён HTTPS на порту 443, проверяются все адреса DNS, соединение открывается по проверенному IP с исходными Host и TLS SNI. Редиректы, прокси окружения, сжатые ответы, внутренние адреса и ответы свыше 512 КиБ отклоняются. Время одной загрузки ограничено 18 секундами. Логи приложения содержат типы ошибок и номера источников. Адрес источника с query-параметрами хранится в БД, поэтому используйте только публичные ссылки.
