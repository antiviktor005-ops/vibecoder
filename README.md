# VibeWorker AI

Личный Telegram-бот для работы с фриланс-заказами. Сохраните ТЗ, получите оценку и черновик отклика, соберите небольшой одностраничный сайт. Для фонового поиска добавьте публичную RSS/Atom-ленту или совместимый JSON API. Интерфейс на русском языке.

## Первый заказ

1. Откройте личный чат бота и нажмите `/start`.
2. Отправьте сообщение с первой строкой `/add Сайт для кофейни`. Со следующей строки опишите необходимые разделы, аудиторию и пожелания.
3. Откройте заказ командой `/jobs 1`, подставив полученный номер. В карточке есть кнопки анализа, отклика и создания сайта.
4. Бот отправит ZIP в ваш чат. Распакуйте его и откройте `index.html`. Повторно скачать архив можно через `/projects ID`.

| Команда | Действие |
| --- | --- |
| `/start`, `/help` | Меню и инструкция |
| `/status` | Проверка БД, состояние планировщика, наличие ключа ИИ и время последнего прохода |
| `/settings` | Ключевые слова через запятую, минимальный бюджет в рублях, максимальная сложность и уведомления |
| `/add ТЗ` | Добавить заказ вручную |
| `/jobs`, `/jobs ID` | Последние 15 заказов или карточка по номеру |
| `/analyze ID` | Сложность, стек, сроки, риски и оценка цены |
| `/reply ID` | Подготовить черновик для проверки владельцем |
| `/site ID` | Создать ZIP с HTML, CSS и JS |
| `/projects`, `/projects ID` | Последние 15 сайтов или повторная отправка архива по номеру |
| `/feeds`, `/feeds run` | Управление источниками, результаты обхода и ручной поиск |
| `/budget` | Запросы, токены, зарезервированный и расчётный расход за сутки UTC |

Система отправляет сообщения и документы только администратору. Публикация сайта и передача отклика заказчику остаются ручными действиями.

## Источники и фильтры

Добавьте адрес командой `/feeds rss HTTPS_URL` для RSS/Atom или `/feeds api HTTPS_URL` для JSON. Адрес должен сразу возвращать данные через HTTPS на порту 443. Используйте общедоступные источники, разрешающие такую загрузку. Учётные данные и токены в URL не нужны. Список источников при первом запуске пуст. Интеграции с Kwork и Telegram-каналами в MVP отсутствуют.

```text
/settings слова python, лендинг
/settings бюджет 10000
/settings сложность 2
/settings уведомления вкл
/feeds run
```

Совпадения любого слова достаточно. При положительном минимуме цены требуется известная сумма в рублях. Уровни сложности от 1 до 3. При максимуме 3 допускается неизвестная сложность. RSS-адаптер распознаёт простую запись суммы с ₽, «руб» или RUB и запись «Сложность: 2». Он не оценивает произвольное ТЗ автоматически. Заказы, добавленные вручную, сохраняются независимо от фильтров.

Для JSON поддерживаются массив объектов или объект с массивом `jobs`. Пример записи:

```json
{"jobs":[{"id":"landing-17","title":"Лендинг кофейни","description":"Меню и контакты","budget_rub":18000,"level":1,"url":"https://example.org/jobs/17"}]}
```

Обязательно поле `title`. Стабильный `url` либо `id` улучшает дедупликацию. Ошибка одной ленты отражается в `/feeds`, остальные проверяются дальше. Отключить источник можно через `/feeds off ID`, включить через `/feeds on ID`.

## Локальный запуск

Потребуются Python 3.12+, отдельная PostgreSQL и токен Telegram-бота. В корне проекта создайте окружение и активируйте его.

```sh
python -m venv .venv
# Linux/macOS
. .venv/bin/activate
# Windows PowerShell
# .\.venv\Scripts\Activate.ps1
python -m pip install ".[dev]"
```

Скопируйте `.env.example` в `.env`. Заполните `BOT_TOKEN`, числовой `ADMIN_TELEGRAM_ID` и `DATABASE_URL`. Для ИИ укажите `OPENAI_API_KEY`, модель с поддержкой Chat Completions и JSON mode, а также соответствующие тарифы за 1 млн токенов. Значения в примере рассчитаны для `gpt-4o-mini`. Перед запуском сверьте ставки выбранной модели. [Тарифы OpenAI](https://openai.com/api/pricing/)

```sh
python -m scripts.migrate
python -m app.main
```

Для разработки с Docker соберите образ командой `docker build -t vibeworker-ai .`. Примените миграции через `docker run --rm --env-file .env vibeworker-ai python -m scripts.migrate`, затем запустите `docker run --rm --env-file .env vibeworker-ai`. Адрес БД должен быть доступен из контейнера.

## Проверка

```sh
ruff check .
ruff format --check .
python -m pytest -q
```

Для полного теста задайте `TEST_DATABASE_URL` для отдельной тестовой PostgreSQL. Тест создаёт изолированную схему, применяет миграцию и проверяет параллельные запросы. Без этой переменной данный тест пропускается. Остальные проверки используют SQLite в памяти и подменяют внешние API. GitHub Actions поднимает PostgreSQL 16, запускает миграцию, проверку схемы, тесты и сборку образа.

Подробности запуска на Railway и устройства worker приведены в [инструкции по развёртыванию](DEPLOY_RAILWAY.md) и [описании архитектуры](ARCHITECTURE.md).
