# Запуск на Railway

Один сервис выполняет Telegram long polling и периодический поиск. Второй сервис хранит PostgreSQL. Постоянная работа зависит от тарифа, доступных средств и состояния обоих сервисов. Перед созданием ресурсов проверьте стоимость в своём аккаунте. [Тарифы Railway](https://railway.com/pricing)

1. В Telegram создайте бота через BotFather. Сохраните выданный токен и узнайте свой числовой Telegram ID. Откройте чат бота и нажмите Start.
2. Когда будете готовы оплачивать инфраструктуру, создайте проект Railway и добавьте PostgreSQL. Оставьте БД в том же проекте и окружении, что и worker.
3. Добавьте сервис из GitHub-репозитория `antiviktor005-ops/vibecoder`, выберите ветку `main` и корень репозитория. Railway прочитает Dockerfile и `railway.json`. Если первая сборка стартовала до ввода переменных, примените их и выполните Redeploy.
4. В Variables **сервиса worker** добавьте значения из таблицы. Для БД используйте Add Reference и выберите переменную DATABASE_URL сервиса Postgres. Если он называется `Postgres`, ссылка выглядит как `${{Postgres.DATABASE_URL}}`. Для другого имени выберите соответствующий сервис в интерфейсе.
5. Оставьте одну реплику в одном регионе. Конфигурация отключает сон, устанавливает нулевое перекрытие версий и даёт 30 секунд на завершение. Публичный домен, HTTP healthcheck, cron и PORT для worker не требуются. Остановите локальный экземпляр с тем же токеном.
6. В настройках Source оставьте автодеплой из `main`, включите Wait for CI, если этот переключатель доступен. Отдельные окружения для pull request должны использовать свой токен, если у них включён запуск бота.
7. Примените изменения. Дождитесь «Схема БД обновлена» на этапе pre-deploy и «Worker запущен» в логах. Проверьте `/status`, добавьте заказ через `/add`, затем настройте `/feeds`. Для проверки ИИ используйте `/analyze ID`. Это реальный запрос с расходом по тарифу модели.

| Переменная | Значение |
| --- | --- |
| BOT_TOKEN | Секрет из BotFather |
| ADMIN_TELEGRAM_ID | Числовой ID единственного владельца |
| ALLOWED_USER_IDS | Совместимость конфигурации. Дополнительных прав не даёт. Можно оставить пустой |
| DATABASE_URL | Reference на PostgreSQL в этом окружении |
| OPENAI_API_KEY | Опционально. Без него работают меню, источники, заказы, фильтры, история и скачивание существующих ZIP |
| OPENAI_MODEL | По умолчанию gpt-4o-mini |
| APP_ENV, LOG_LEVEL | production и INFO |
| SEARCH_INTERVAL_MINUTES | 30 по умолчанию |
| AI_DAILY_REQUEST_LIMIT | Максимум запросов за сутки UTC |
| AI_DAILY_TOKEN_LIMIT | Максимум входных и выходных токенов вместе с резервами |
| AI_DAILY_BUDGET_USD | Расчётный суточный лимит в долларах |
| AI_INPUT_USD_PER_MILLION, AI_OUTPUT_USD_PER_MILLION | Цены модели. Задавайте обе явно при смене модели |

## Эксплуатация

Railway выполняет `python -m scripts.migrate` до старта приложения. При ошибке миграции проверьте reference variable, доступность БД и права на изменение схемы. Worker повторяет подключение с увеличением задержки. После аварийного выхода настроено до десяти перезапусков. Если они исчерпаны, устраните причину и запустите Redeploy. [Pre-deploy](https://docs.railway.com/deployments/pre-deploy-command) · [Конфигурация сервиса](https://docs.railway.com/config-as-code/reference)

Состояние хранится в PostgreSQL, включая двоичные ZIP. Настройте резервные копии PostgreSQL и проверьте восстановление в отдельном окружении. Замена контейнера worker не требует переноса его диска. Секреты храните в Variables. Не помещайте `.env` в репозиторий.

Если Telegram отвечает конфликтом polling, проверьте количество экземпляров с этим токеном. Для диагностики источника смотрите `/feeds`. Для ответа HTTP 301/302 задайте конечный URL. При HTTP 403/429 соблюдайте ограничения площадки. Расход запросов с неизвестным результатом учитывается до следующих суток UTC.
